# Dye Finder · Web Preview 0.1

A local browser preview of the Windows dye finder. Screenshots, search and feedback ZIPs are processed in your browser. No account, image server or automatic upload is used.

## Start locally

Use Node.js 24. From this `web` directory:

```powershell
npm ci
npm test
npm run build
./Start-Web.cmd
```

The launcher opens `http://127.0.0.1:4173/` and runs its local server in the background. `Stop-Web.cmd` stops only the server started by this folder. The packaged preview includes the built files, so it needs no npm installation or build. A static HTTP server is required: opening `dist/index.html` directly as a file cannot reliably load an ES-module Worker.

For development use `npm run dev`. For a different preview port use `./Start-Web.ps1 -Port 4180` and `./Stop-Web.ps1 -Port 4180`.

## Use it

Open a screenshot or **Try Demo**, choose colors, adjust visible **Color Tolerance**, then click **Find Matches**. Import detects the board; it does not run a search. Select one of three spots and click any numbered point to inspect it in the shared zoom preview. Yellow rings mark original crosses, cyan rings mark suggested points, and white marks the selected point.

Under **Advanced**, select the board manually and mark its six original crosses, top row left to right then bottom row. Settings can be saved in this browser or imported/exported as JSON; desktop schema 1 preferences are accepted. RGB values must be integers 0–255, tolerance 1–40, with at most 30 colors and 40 characters per name.

**Record Result** downloads a trial ZIP. **Found nearby** and **Not useful** cannot label the original recommendation with game RGB. **Matched here** can optionally include six manually verified values. **Report a Problem** creates a separate record even without a screenshot or suggestion. Optional screenshots require crop review. Downloading only confirms that a download was started; review the actual ZIP in your browser downloads before sharing.

## Validation and limits

The TypeScript port preserves the desktop 0.3.4 / ranker-v1 rules. Golden fixtures generated by unchanged C# code check Lab, CIEDE2000, geometry, masks, six-slot estimates, coordinates and ranking. See [TESTING.md](TESTING.md) for evidence and remaining browser acceptance work.

This is a local preview, with Chrome and Codex's Chromium browser checked. Edge, Firefox and Safari, image color profiles, JPEG/EXIF differences, high DPI and full performance/memory acceptance remain to be verified. Successful checks do not establish accuracy in the game. The sampler is independently identified as `browser-srgb-v1`.

Images stay in page memory; localStorage contains settings only. The app loads its static resources and a same-origin version file; a hosting provider may log resource requests. No Service Worker is installed, and offline cold starts are not promised. Closing or refreshing the page requires reimporting your image. Older cached pages can show a reload prompt when the initial version check finds a newer version.

## Static build

`npm run build` bundles dependencies, the Worker, license notices and the intentional real demo into `dist`. `npm run check:dist` checks its file allowlist, required assets and absence of source maps, local paths and internal notes. The default relative Vite base supports local subdirectories. For a future GitHub Pages project build:

```powershell
$env:WEB_BASE = '/vindictus-dye-finder/'
npm run build
```

The separate web Actions workflow checks and saves an artifact; it does not deploy or publish a desktop release. No hosted URL has been created for this preview.
